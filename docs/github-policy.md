# GitHub Policy

StewartOS uses GitHub for source control, backup, collaboration, and public credibility.

## Default Rule

Real code belongs in GitHub. Sensitive code belongs in private GitHub. Public GitHub is for intentional, sanitized showcase work.

## Private Repos

Use private repos for:

- Product source code.
- Business strategy.
- Client work.
- Internal tools.
- Active prototypes.
- Systems with secrets, personal context, or unclear licensing.

## Public Repos

Use public repos for:

- Polished reusable tools.
- Portfolio-quality demos.
- Sanitized architecture patterns.
- Open-source-style libraries.
- Public marketing or documentation sites.

## Never Commit

- `.env` files.
- API keys or tokens.
- Local auth state.
- Personal/family data.
- Client data.
- Raw inbox/calendar exports.
- Generated runtime databases.
- Large build outputs or cache folders.
